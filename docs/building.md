# Building and contributing

The built fonts are committed, so you only need this page to change the fonts or update an upstream source.

## Requirements

- [uv](https://docs.astral.sh/uv/). `build.py` declares its own dependencies (fontTools, brotli) inline, and uv installs them on first run.
- Optional: LuaLaTeX to check the LaTeX package, and Chrome or Firefox to check the specimen.

## Build and test

```sh
uv run build.py
uv run --with pytest --with fonttools --with brotli pytest -q tests
```

`build.py` clears `fonts/desktop/` and `fonts/web/`, then for each upstream file:

1. Rewrites the family-name records (IDs 1, 3, 4, 6, 16, 17, 18, 20, 21, 22, 25 and any variable-instance names), and the CFF names in Sans Math. It sets the version string and vendor ID, adds a modification notice to the copyright line, and drops legacy Mac-platform name records.
2. Sets the shared vertical metrics and widens the Windows clipping box to the glyph bounds.
3. Asserts that the glyph count and the MATH table survived.
4. Writes the desktop file and a WOFF2.
5. For variable sources, cuts static Regular and Bold instances (and their italics) for `fonts/desktop/*/static/`.

Then it writes `css/datacraft.css` and `fonts/manifest.json` and copies the licenses next to the fonts.

### What the tests check

| Test | Fails when |
|---|---|
| `test_every_source_was_built` | a source was skipped, or extra files appeared |
| `test_no_upstream_name_in_family_records` | "STIX", "Fira", "JetBrains" or "TM Math" survives in a family-name record or CFF name |
| `test_shared_vertical_metrics` | any metric differs from the shared values, or the Windows box clips a glyph |
| `test_licence_and_copyright_kept` | the copyright or OFL license record went missing |
| `test_math_fonts_keep_math_table` | a math face lost its MATH table |
| `test_canary_leak_check_sees_upstream_names` | the name check stopped detecting upstream names, which would make the second test pass vacuously |

## Changing the design

All decisions live in constants at the top of `build.py`:

| Constant | Controls |
|---|---|
| `ASCENDER`, `DESCENDER` | shared vertical metrics |
| `FAMILIES` | which upstream files become which Datacraft family |
| `FIRA_WEIGHTS` | which Sans weights ship |
| `STATIC_WEIGHTS` | which static instances are cut from variable sources |
| `VERSION`, `VENDOR` | version string and vendor ID |

The CSS is generated by `write_css()`; edit it there, not in `css/datacraft.css`.

## Updating an upstream font

1. Download the new release into its `sources/upstream/<name>/` directory, replacing the old files and keeping the license file current.
2. Update the version and date in `sources/INDEX.md`.
3. Run the build and the tests, then open `specimen/index.html` and compile `latex/sample.tex`.
4. If a filename changed, update the matching `Family` entry in `build.py`.

Only take upstream files under the SIL Open Font License, and check the license for new Reserved Font Names. A reserved name must not appear in any Datacraft family name; add it to `UPSTREAM_NAMES` in the tests.

## Releasing

1. Bump `VERSION` in `build.py`, rebuild and test.
2. Add an entry to `CHANGELOG.md`.
3. Commit, then tag: `git tag v1.1.0 && git push --tags`.
4. Build the two archives and attach them to a GitHub release:

```sh
v=1.1.0
zip -r "datacraft-fonts-desktop-$v.zip" fonts/desktop latex/datacraft.sty
zip -r "datacraft-fonts-web-$v.zip" fonts/web css
gh release create "v$v" datacraft-fonts-*-$v.zip --notes-file <(sed -n "/^## $v/,/^## /p" CHANGELOG.md | sed '$d')
```

## License obligations

Datacraft inherits the SIL Open Font License 1.1 from every upstream font. In practice:

- Ship the license text with the fonts. The build copies it next to every font file.
- Keep the upstream copyright notices. The build leaves name ID 0 intact and only appends to it.
- Don't sell the fonts on their own. Bundling them with software, documents or a website is fine.
- A modified version must not use a Reserved Font Name. STIX reserves "TM Math"; no Datacraft family uses it.
